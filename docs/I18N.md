# Internationalization design

## Goals

- Give every rendered language version a stable, explicit URL.
- Keep the Astro site statically generated.
- Use Cloudflare only to route language-neutral entry points.
- Allow partial translation: a post does not need to exist in every locale.
- Preserve existing `/posts/<slug>/` links as neutral compatibility URLs.

## Locales

| URL path | Content locale | HTML / hreflang |
| --- | --- | --- |
| `en` | English | `en` |
| `zh` | Simplified Chinese | `zh-CN` |
| `ja` | Japanese | `ja` |

English is the deterministic fallback. Existing `lang: jp` content is
normalized to `ja`; existing `zh_CN` content is normalized to `zh`.

## URLs

Actual content has a locale prefix:

```text
/en/posts/<translation-key>/
/zh/posts/<translation-key>/
/ja/posts/<translation-key>/
```

Language-neutral URLs are dispatchers:

```text
/
/posts/<translation-key>/
/about/
/archive/
/contact/
/series/
/series/<series-key>/
```

The Cloudflare Worker chooses a target using:

1. an explicit locale URL (never redirected);
2. the `locale` cookie;
3. the request `Accept-Language` preferences;
4. English.

Dispatch redirects are temporary and non-cacheable. If the preferred
translation does not exist, the Worker falls back to English and then to any
available translation.

## Content identity

Translated Markdown entries share a `translationKey`:

```yaml
lang: en
translationKey: ai-made-code-cheap
```

```yaml
lang: zh_CN
translationKey: ai-made-code-cheap
```

The collection entry ID remains an implementation detail. Public post URLs use
`translationKey`, so translated files may use suffixes such as `.zh.md`
without changing the public slug.

## SEO

Every localized post:

- has a self-referencing canonical URL;
- lists itself and all available translations with reciprocal `hreflang`;
- points `hreflang="x-default"` to the neutral dispatcher;
- sets `<html lang>` and JSON-LD `inLanguage` to the rendered locale.

Missing translations do not generate a localized page and are never rewritten
under the wrong locale prefix.

## Compatibility

The original unprefixed pages remain in the static output during migration.
Cloudflare intercepts neutral home, post, profile, archive, contact, and series
routes before static asset serving.
If the Worker is absent (for example, plain `astro preview`), the old English
page remains a usable fallback.

## Phase two

- About and Contact use the same explicit-locale and translation-key model as
  posts.
- Series indexes are generated per locale and only contain posts in that
  locale.
- A series detail page exists only when that series has at least one post in
  the requested locale.
- Neutral non-post routes preserve query parameters when dispatching.
